## 执行规则

每次任务先执行轻量分类，不等于每次都重新执行完整门禁：

1. 判断任务是否引入新功能、新资源或改变既有 SDK/渲染契约。
2. 选择完整门禁、增量门禁、免重复门禁或无需门禁。
3. 只收集当前模式所需证据，不重复询问已由当前工程和本次上下文确认的内容。
4. 完整/增量门禁必须运行 `inspect_android_project.py ... --gate` 并输出资源表；非零退出时不得开始受影响功能；免重复门禁输出简短复用结论；只读任务直接开展诊断或审查。
5. 实施过程中发现门禁失效条件时，暂停受影响修改并切换为增量门禁。

项目中发现文件只表示“已发现待确认”。AAR、模型、lic 和素材必须确认属于同一套兼容交付，lic 还必须匹配最终构建变体的 applicationId。不要读取或展示 lic 内容。

## 授权资源发现范围

执行门禁前先记录用户本次明确授权的输入，资源证据只允许来自：

1. 用户指定的目标 Android 工程路径及其内部文件。
2. 用户直接附加或明确提供的单个文件。
3. 用户明确给出的、允许查找资源的目录路径。
4. 用户明确提供的受支持依赖坐标或供应方资料。

目标工程外路径不因位于当前工作区、仓库、父目录或构建脚本中而自动获得读取授权。必须遵守：

- 禁止递归扫描目标工程父目录、工作区根目录、兄弟工程、下载目录、用户目录或 skill 目录寻找 AAR、lic、模型和素材。
- 构建文件引用工程外本地路径时，只记录“存在外部引用”；先让用户确认该精确路径可读取，再检查文件。
- 不把当前会话偶然可见、其他任务遗留或同仓库兄弟工程中的文件认定为客户已提供资源。
- `inspect_android_project.py` 默认只扫描目标工程。仅当用户明确提供工程外资源文件或目录时，才传 `--resource-path <path>`；每个参数必须能对应到用户原始输入。
- 路径不存在、不可访问或未找到所需文件时，不尝试相邻路径、常见安装目录或网络搜索；直接列出缺失项、格式/版本要求、用途和解除动作。只要该项会影响编译、SDK 初始化、功能运行或效果输出，就暂停受影响接入，等待用户明确提供并重新通过门禁。

“已提供”表示用户附加文件、指定文件路径、指定可搜索目录，或目标工程内部已经包含该文件；仅凭文件名相似、工作区可见或历史任务记忆不算已提供。

## 任务分类与门禁模式

| 任务类型 | 门禁模式 | 行为 |
| --- | --- | --- |
| 项目首次接入 NveEffectKit | 完整门禁 | 盘点通用条件及本次全部功能依赖，输出完整清单 |
| 为现有 NVE 管线新增最终输出录制 | 宿主能力门禁 | 确认现有 `renderEffect` 最终纹理消费点、模块、GL 线程、MediaStore、编码能力、空间和麦克风权限；不重新盘点既有 NVE AAR/lic/模型/素材 |
| 已接入项目新增功能或功能变体 | 增量门禁 | 复用未变化基线，只列新增功能带来的依赖差异 |
| 更换 SDK/AAR、lic、模型、素材、ABI 或渲染契约 | 增量门禁 | 只重新检查受变化影响的功能；无法确认影响边界时升级为完整门禁 |
| 调整现有效果参数、UI、状态保存或无新依赖的性能优化 | 免重复门禁 | 验证未命中失效条件后直接实施，不输出完整资源表 |
| 修复现有功能代码问题 | 免重复门禁或增量门禁 | 普通逻辑/生命周期修复免重复；涉及授权、模型、素材、ABI、API 或渲染契约时只检查相关项 |
| 黑屏、无效果、崩溃等问题诊断 | 无需门禁 | 先只读定位原因；如果要实施涉及前置条件的修复，再切换为增量门禁 |
| 代码审查、接入评估或方案说明 | 无需门禁 | 不因资源缺失阻止分析，明确证据不足和未验证风险即可 |

同一请求同时包含多类任务时分别处理。例如“修复美颜状态恢复并新增道具”中，美颜修复可免重复门禁，道具新增执行增量门禁。

## 基线复用与失效

优先从当前工程的构建配置、实际 AAR、接入代码、资源布局、已有测试结果和当前任务上下文复用基线。不要只依赖跨任务记忆，也不要为了记录门禁状态在客户工程中新建标记文件。

同时满足以下条件时可免重复门禁：目标工程和模块相同、功能已存在、本次不新增资源/API、AAR/SDK 与最终 applicationId 未变化、ABI 与输入输出渲染契约未变化。证据不足时只对不确定项做增量检查，不默认回退到完整门禁。

以下变化会使相关基线失效：

- 新增此前未接入的功能，或从内置效果切换为素材包效果。
- NveEffectKit AAR、其他美摄 SDK 组件、模型或素材版本变化。
- applicationId、productFlavor、applicationIdSuffix、授权主体或 lic 变化。
- ABI、minSdk、打包方式或测试设备架构变化。
- OES/2D/Buffer 输入、渲染模式、输出消费方、方向镜像责任或 GLContext 所有权变化。
- 当前问题指向授权失败、模型初始化失败、素材安装失败、重复 SDK 类或 ABI 缺失。

失效只影响相关范围。例如更换道具素材不要求重新盘点基础美颜；更换 AAR 可能影响全部功能，需要重新核实其 API、ABI、内嵌依赖及配套资源。

## 状态与阻塞等级

状态只使用以下值：

| 状态 | 含义 |
| --- | --- |
| `已确认` | 来源、版本、用途和必要绑定关系均已确认 |
| `已发现待确认` | 工程中发现候选文件或调用，但版本、来源或绑定关系尚未确认 |
| `缺失` | 已确认本次需要，但客户工程和交付物中均未提供 |
| `无法判断` | 静态盘点不能确认，需要客户补充最小信息 |
| `不适用` | 当前功能不依赖该资源 |

阻塞等级只使用以下值：

| 等级 | 执行约束 |
| --- | --- |
| `硬阻塞` | 禁止开始代码接入，例如 AAR/API 或渲染接入点无法确认 |
| `功能阻塞` | 暂停依赖该资源的功能并要求用户补充；其他已满足前置条件的独立功能可继续 |
| `验证阻塞` | 仅缺设备、视觉证据或发布矩阵；可继续代码和构建，但不得宣称对应验收通过 |
| `提示` | 记录风险和补测项后继续 |

## 通用前置条件

所有 NVE 特效功能先检查：

| 资源或信息 | 必需性 | 默认阻塞等级 | 确认标准 |
| --- | --- | --- | --- |
| NveEffectKit AAR/API | 必需 | 硬阻塞 | 已提供实际 AAR 或受支持的依赖坐标，并能确认公开 API、ABI 和内嵌依赖 |
| 目标模块与接入点 | 必需 | 硬阻塞 | 已识别消费 SDK 的模块、输入帧类型、输出消费方和有效 GLContext 所在线程 |
| SDK lic | 运行必需 | 功能阻塞 | 已确认 lic 来源及其绑定的最终 applicationId；无需读取 lic 内容 |
| SDK/AAR 配套版本 | 必需 | 硬阻塞 | 模型、原生库及其他美摄组件与当前 AAR 属于兼容交付 |
| ABI 与测试设备 | 构建/验收必需 | 硬阻塞或验证阻塞 | 应用目标 ABI 必须在 AAR 中存在；仅缺匹配真机时为验证阻塞 |
| 相机方向与镜像契约 | 验收必需 | 提示 | 已明确前后摄、旋转、镜像和纹理翻转责任方 |

缺少本次能力所需 lic、模型、素材、素材 lic、兼容版本或实际路径时，直接向用户输出最小前置条件清单并暂停受影响功能，提供并重新检查后再执行。不得提前生成该功能的控制器、占位 UI、假路径或假资源，也不得借用其他工程的交付物。仅缺真机或人工视觉证据、且现有资源足以编译和运行时，才按验证阻塞继续。

`recording` 只消费现有 NVE 最终输出，不重新执行上述 NVE 资源条件。必须发现可信的
`renderEffect` 最终纹理消费点，再确认目标模块、共享 GLContext、编码器能力、MediaStore、
空间和可选麦克风权限；未发现最终输出时阻塞录制，并明确不转为通用相机录制。录制与新增
NVE 特效同时接入时分别计算：新增特效仍受对应资源门禁，录制等待其最终输出闭环。

## 功能依赖矩阵

下表是在通用前置条件之外追加的最小依赖。最终模型类型和素材授权要求以当前 AAR、配套交付说明及素材元数据为准。

范围先用 `scripts/feature_contract.py --features <csv>` 解析。命中
`scope_selection_required` 时使用报告中的 `selection_requests` 询问并等待答复，不自行选择
“常用”子集。资源目录只授权发现；只有用户明确要求按交付能力接入时，才由已授权资源映射
leaf feature。内部 Beauty AR Scene 锚点仍属于美型/微整形的运行时依赖。

| 功能 | 追加前置条件 | 不应默认要求 |
| --- | --- | --- |
| NVE 最终输出录制 `recording` | 现有 `renderEffect` 最终输出纹理及方向/镜像契约、共享 EGL 编码线程、MediaRecorder/MediaStore、可用空间、可选麦克风权限、真机编码能力 | 为单独新增录制重新索取既有 NVE AAR、SDK lic、模型或特效素材 |
| 完整美颜（仅显式“完整/全部”） | 合并下列美肤、美型、微整形的全部实际依赖 | 美妆、道具、分割、Avatar、滤镜素材 |
| 美肤 `beauty-skin` | 登记 3.16.1 基线必须按 `FACE → FACE_COMMON → ADVANCED_BEAUTY` 初始化；其他 AAR 使用其正式配套清单 | 美型/微整形素材、道具、分割、Avatar、滤镜素材 |
| 美型 | 登记 3.16.1 基线必须按 `FACE → FACE_COMMON` 初始化；逐子项核对显式素材映射、包类型和安装结果 | 美妆、道具、分割素材 |
| 微整形 | 登记 3.16.1 基线必须按 `FACE → FACE_COMMON` 初始化；逐子项核对显式形变素材映射，四个内置项除外 | 与所选参数无关的形变包 |
| 单妆/妆容 | 当前版本要求的人脸通用/高级美颜模型、组成素材包、必要素材 lic、完整元数据及引用包；`Eyeball` 等分类按素材声明追加 `EYEBALL` | 道具和分割模型，除非素材声明依赖 |
| 内置滤镜 | 当前 AAR 中可确认的内置效果名称或 API | `.videofx`、素材 lic、无关人脸模型 |
| 素材滤镜 | 选定滤镜逐项映射 `.videofx`、素材 lic 状态、安装类型和素材元数据；妆容组成 `.videofx` 不算独立滤镜 | 道具或美妆素材 |
| 人脸道具 | `.arscene`、`FACE`；按素材声明追加 `FAKE_FACE`、`EYEBALL`、`SEGMENTATION` 或 `AVATAR` | 未被素材声明的附加模型 |
| 自定义背景分割 | 当前版本的人脸相关模型、`SEGMENTATION`、已确认的特效名称和参数契约 | 道具或美妆包 |
| 其他自定义特效 | 当前 AAR 的特效契约，以及该特效明确声明的模型和素材 | 根据功能名称猜测的模型或包 |

登记 3.16.1 基线的精确文件、顺序和子项映射由 `feature_contract.py` 从登记 catalog
输出；其他 AAR 不能套用该数据。
模型类型的技术含义、版本下限、素材扩展名和安装规则读取
[assets-and-models.md](assets-and-models.md)。不能根据不匹配版本的外部资源文件名、素材 UUID
或展示名称推断客户所需资源。

## 资源获取方式

只提供已确认的官方渠道。文档没有公开下载地址时明确说明，不虚构直链。

| 资源 | 获取方式 | 联系或下载时提供的信息 |
| --- | --- | --- |
| 人脸版本 SDK | 从[美摄官方下载页](https://www.meishesdk.com/downloads)获取正式的人脸版本 Android SDK 包 | Android 平台、目标 SDK 版本和所需能力 |
| SDK lic | 联系[美摄商务](https://www.meishesdk.com/)获取 | 最终 applicationId、Android 平台、SDK/AAR 版本、目标功能和使用环境；不要发送 lic 内容到日志或公开渠道 |
| NveEffectKit AAR | 先检查正式项目交付包；当前资料没有独立公开下载地址，缺失时联系项目交付人员或[美摄技术支持](https://www.meishesdk.com/) | Android 平台、已有美摄组件版本、目标功能和所需 ABI |
| 人脸/高级美颜/分割等模型 | 只从与当前 AAR 配套的正式 SDK 交付中取得；交付中缺失时联系[美摄技术支持](https://www.meishesdk.com/) | AAR/SDK 版本、需要的 `NveDetectionModelType` 和目标功能，不猜测模型文件名 |
| 商业素材与素材 lic | 使用客户已购买或正式交付的资源；缺失时联系美摄商务或项目交付人员 | 素材类别、目标功能、SDK 版本及授权主体 |
| 素材安装说明 | 阅读[素材包安装文档](https://www.meishesdk.com/android/doc_en/html/content/assetsPackageInstall_8md.html) | 无 |
| 素材包类型 | 查阅[`NvsAssetPackageManager` 官方文档](https://www.meishesdk.com/android/doc_en/html/content/classcom_1_1meicam_1_1sdk_1_1NvsAssetPackageManager.html) | 当前素材扩展名和 SDK 版本 |

不得把未经授权的目标工程外路径描述为客户获取渠道，也不得建议从其他工程复制 AAR、lic、模型或商业素材。

## 输出格式

完整门禁在首次修改代码前输出全部相关项；增量门禁使用相同表格，但只输出新增、变化、失效或无法判断的项目。字段顺序固定：

| 资源项 | 适用功能 | 必需性 | 当前状态 | 证据 | 获取方式 | 阻塞等级 | 阻塞原因 | 解除动作 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| NveEffectKit AAR | 美颜、美型 | 必需 | 缺失 | 用户授权范围内未提供或未找到 AAR | 检查正式交付包；否则联系项目交付人员或技术支持 | 硬阻塞 | 无法确认 API、ABI 和依赖 | 明确提供实际 AAR、受支持依赖坐标或可搜索目录 |
| SDK lic | 美颜、美型 | 运行必需 | 已发现待确认 | 工程内发现 lic，但未验证绑定关系 | 联系商务确认 | 功能阻塞 | 无法确认 SDK 初始化和效果输出 | 确认 lic 与最终 applicationId 匹配 |
| 人脸/高级美颜模型 | 美颜、美型 | 按版本必需 | 无法判断 | 仅凭文件名不能确认模型类型和版本 | 从配套 SDK 交付取得；否则联系技术支持 | 功能阻塞 | 无法确认对应能力可以初始化 | 提供模型类型、配套版本和实际路径 |
| `.facemesh`/`.warp` | 美型 | 条件必需 | 无法判断 | 尚未确认所选美型是否由素材驱动 | 使用已购买或正式交付素材；否则联系商务或项目交付人员 | 功能阻塞 | 素材驱动的美型无法创建 | 确认美型实现类型；需要素材时提供包及必要素材 lic |

表格后必须给出：

1. `当前可执行范围`：可继续的实现、构建或分析阶段。
2. `已阻塞范围`：被哪个资源阻塞的具体功能或验证阶段。
3. `需要客户补充`：只列无法从工程确认的最小信息，不重复已确认项。

默认不输出“本次不需要”。仅当功能名称容易引发资源范围误解、用户已准备提供无关资源，或排除项会直接影响后续采购/交付决策时，才补充 `本次不需要`，并只列与当前误解直接相关的无关模型或素材。

证据只记录相对路径、数量、类型或静态调用线索；不展示 lic 内容、签名参数下载地址、密钥或商业素材内容。

免重复门禁不输出资源表，使用简短结论：

```text
门禁模式：免重复门禁。当前工程已存在目标功能，本次仅修改 <范围>；AAR/SDK、applicationId、ABI、模型/素材及渲染契约未变化，无新增前置资源。
```

只读诊断/审查不输出门禁结论；直接报告发现、证据和未覆盖风险。若用户随后要求实施修复，再按修复范围重新分类。

## 门禁决策

- 存在硬阻塞：停止受影响代码接入，输出清单和解除动作；不影响只读诊断和其他独立功能。
- 存在功能阻塞：告知用户缺失项、用途、要求和解除动作，停止受影响功能；不先生成该功能的静态骨架或 UI，其他已满足门禁的请求功能可继续。
- 素材缺失或缺少可信 `feature → path` 映射，只阻塞显式选择且确实依赖该素材的具体项；
  自制/更新素材不得因文件名不同被拒绝。未选择项和仅存在于未经授权外部目录的
  候选项不得进入缺失清单。模型按最终选择功能计算，缺失任何必需模型都阻塞依赖它的全部项。
- 滤镜映射分成唯一 `packages` 与 `display_items`：多个展示项可引用同一 package，且必须
  保留为独立 UI 项；同一包只安装一次。重复 package key、一个 package key 指向多个包、
  展示 ID 重复或引用不存在时阻塞。仅发现其他模块中的 `.videofx`、未声明素材 lic 状态，
  或元数据声明 lic 但授权范围内缺失且未获明确豁免时也阻塞。`license: null` 必须记录
  `license_basis` 为用户确认或正式交付确认，不能由文件缺失自动推断。
- 只有验证阻塞：继续代码和最小构建，并明确缺少的设备/视觉/发布证据；不得把 lic、模型、素材或 ABI 不匹配降级成纯验证阻塞。
- 只有提示：继续实施，并将提示转为验收补测项。
- 新发现功能变体或新增需求：重新计算依赖并再次输出门禁差异，不能沿用旧清单直接扩展。
- 确认免重复门禁：直接执行当前优化或修复，不重复索取资源，不把历史验证阻塞误当成本次代码修改阻塞。
- 只读诊断/审查：不执行资源门禁；资源缺失可以是诊断结论，但不能阻止继续定位。
