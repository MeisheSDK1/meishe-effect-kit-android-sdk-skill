## 决策顺序

按以下顺序决定 UI。只有前两级都不存在时，才使用 skill 内已固化并完成设备验收的
第三级默认设计；该默认设计由本 skill 的 UI 模板和 catalog 完整定义，不访问、不搜索、
也不依赖任何未经用户授权的目标工程外资源：

1. 用户给出设计稿、交互要求或指定页面时，以该要求为准，并沿用目标页面现有结构。
   只有用户明确要求参考另一个工程且明确授权其精确路径时，才检查该工程的层级、
   面板占比、模块切换、列表密度和收起行为；默认接入不得自行寻找当前 skill 和目标工程外的资源。
2. 工程已有设计体系或同类编辑面板时，复用其组件、设计 token、主题、图标、导航、状态管理和测试约定。
3. 用户没有 UI 要求、目标只是接入和验证，且单效果渲染闭环已经通过、仍需人工控制入口时，提供最小验证界面；默认采用屏幕底部统一入口栏 + 与入口栏互斥显示的低遮挡面板。
4. 用户明确不要 UI，且已有自动化入口或调用接口足以验收时，不新增界面；报告人工视觉项尚未验证。

## 先盘点现有工程

修改布局前只读确认：

- 使用 XML Views、Compose 还是混合架构；Material 版本和现有 UI 依赖。
- 设计系统模块、主题、颜色、字号、间距、圆角、图标和通用控件来源。
- 是否已有相机工具栏、BottomSheet、抽屉、侧栏、调试页或效果编辑面板。
- 页面导航、状态持有、单向数据流、错误提示、加载态和生命周期模式。
- resource ID、`testTag`、`contentDescription`、埋点和项目级 UI 自动化约定。

优先把功能放入已有的效果面板或调试入口。禁止仅为本次接入引入新的 UI 框架、设计系统或导航架构；现有依赖不能满足时，先说明必要性和影响。禁止复制目标工程外未经授权的 Activity、Fragment、Composable、布局或资源作为客户界面。

## 默认最小验证界面

没有产品 UI 要求时，以“效果预览优先、操作足够验证”为目标：

- 使用项目已有的 BottomSheet、可折叠面板或侧栏；没有现成模式时，在屏幕最下方用一个统一背景容器承载本次接入的所有大功能入口。美颜、美妆、滤镜、道具、自定义特效分别算大模块；只接子项时仍归入所属大模块，不为每个参数创建按钮。
- 入口栏和编辑面板不得同时显示。点击模块按钮时隐藏整个入口栏并在最下方展开对应面板；点击面板外空白区域时收起面板并恢复入口栏。面板本体必须消费自身范围内的点击，操作控件或点击面板内部空白不得误收起。
- 同一时刻只允许一个面板展开。统一入口栏负责连接所有面板的展开监听，任一面板展开时先收起其余面板，再隐藏入口栏；不得把互斥逻辑分散成不一致的页面条件。
- 进入预览时默认收起或仅显示当前效果摘要；产品已有面板记忆规则时沿用该规则。
- 默认入口栏贴合底部安全区，不覆盖系统手势区域；模块较多时横向滚动，不压缩成不可读按钮。竖屏使用底部面板；横屏仍保留底部模块入口，展开内容可按项目既有模式使用紧凑侧栏。常规展开态目标不超过可用高度的 `32%`，内容多时面板内部横向/纵向滚动，不无限侵占预览。
- 面板不得长期遮住画面中心、人脸主要区域或关键取景信息。若覆盖布局无法保证，应让预览区域随面板重排，而不是叠加全屏编辑层。
- 子项使用紧凑图标/标签或横向列表；可见 chip/按钮高度通常控制在 `36–44dp`，通过透明
  padding 或父容器保持至少 `48dp` 触摸目标。禁止用等分宽度把少数字文本按钮拉成巨大方块，
  也禁止每个参数占据一整行大按钮。
- 只展示请求范围内的功能。单功能不创建空页签；多分类可复用现有页签/分组，但必须处理窄屏、横屏和长文案溢出。
- 命中登记基线时用 `feature-catalog.json` 将最终选择的 leaf feature 映射成数据源，只生成
  用户选择且前置条件满足的项。仅显式完整美颜覆盖 12/11/21 项，显式完整美妆覆盖妆容和
  9 类单妆；部分接入不展示缺素材或未选择项。禁止用无序 Map 决定 tab 顺序。
- 除非用户明确要求产品化编辑器，不实现全屏编辑页、复杂动效、皮肤系统或无关相机功能。

最低交互闭环包含：功能可用性、选择/开关、请求能力所需的强度控制、重置/移除，以及资源安装或初始化失败后的明确禁用原因。单妆、人脸道具等无强度契约的能力不为界面整齐而虚构滑块。

## 紧凑美颜面板基线

当客户工程没有可复用的效果编辑器，且用户没有指定另一套布局时，美颜、美型和微整形统一采用以下紧凑底部面板。它是验证界面的默认设计，不覆盖客户已有设计系统。

命中登记基线且确认需要默认 Views 面板时，优先通过落地器
`--ui-profile compact-beauty` 生成
`NveCompactBeautyPanelView.java`，再把 catalog 数据适配为模板的 `Item`。已有产品设计系统、
Compose 页面或效果编辑器时不生成此模板，只迁移下面的状态与交互契约。

### 视觉体系

- 使用深色半透明底板 `#F21B1B24`、表面色 `#FF2A2A36`、弱描边
  `#3DFFFFFF` 和粉色强调 `#FFFF6F9F`；宿主有品牌 token 时可替换颜色，但必须保持选中、
  未选中和禁用三个层级。
- 分类必须表现为真正的 Tab：等宽文字区加底部 `28 × 2dp` 强调色指示条，不使用三个
  胶囊按钮。按下态只增加弱表面色，选中态不能靠文字颜色单独表达。
- 功能项固定为“封面 + 下方名称”的紧凑卡片。选中项使用 `2dp` 强调色封面描边和白色
  名称，未选中项使用 `1dp` 弱描边和次级文字；不得使用强调色实底遮盖封面。
- 重置使用弱表面色扁平按钮，不使用粉色胶囊描边。开启控件由固定“开启”文字和无内部
  文案的 Switch 组成一个整体；二者不能拆开放置或分别留间距。
- 当前数值只显示格式化结果，例如 `0.50`、`-0.25`、`10.00`。功能名由上方选中项表达，
  同时写入数值控件的 `contentDescription`，不得在狭窄数值区重复显示功能名。

### 收起态与容器

- 初始收起时，在底部安全区上方显示统一入口栏。入口栏横向撑满可用宽度，左右和底部
  外边距均为 `8dp`，水平内边距 `8dp`、垂直内边距 `6dp`；使用
  `#E61B1B24` 背景、`#3DFFFFFF` 的 `1dp` 描边、`24dp` 圆角和 `10dp` elevation。
- 每个模块占一个等权重的 `36dp` 高槽位，入口按钮在槽位中居中，视觉尺寸为
  `64 × 32dp`。不得直接把按钮本体等权拉伸成大块；通过等宽父槽位实现均匀分布。
- 点击入口后隐藏整个入口栏，面板改为贴合可用区域最下方；入口按钮与面板不得同时出现。
  点击面板外透明空白区域才收起；面板设置为 clickable 并消费内部点击，不增加可见蒙层。
- 竖屏面板采用三行内容，高度收敛到约 `152dp`；参考尺寸为：左右边距 `10dp`、水平内边距
  `8dp`、上下内边距 `6dp`、圆角 `18dp`、底部间距 `0dp`。
- 展开/收起时保持“美颜”文案不变，只用 `selected` 状态表达展开迁移；不得使用大型悬浮按钮遮挡预览。
- 入口视觉高度为 `32dp`，父槽位高 `36dp`，功能卡片触摸区为 `60 × 60dp`。产品界面仍优先遵循宿主
  触摸目标规范；较小控件需要 `48dp` 触摸区时，用不改变视觉尺寸的
  hit slop/TouchDelegate 扩展。

### 三行布局

1. **分类 Tab 行，`40dp`**：按固定顺序等宽放置“美肤 / 美型 / 微整形”，使用文字加底部指示条切换；此行不放总开关和重置。
2. **功能项行，`60dp`**：使用单行横向滚动封面卡片。卡片为 `60 × 60dp`，封面框
   `42 × 42dp`，实际 Bitmap 区 `38 × 38dp`，名称区高 `14dp`、字号 `9sp`，相邻项间隔
   `4dp`。当前项使用强调色描边；不可用项禁用并降低透明度；切换分类后滚回起点。
3. **数值与开关行，`40dp`**：顺序固定为
   `value → slider → reset → master-control`。左侧只显示当前数值，滑块占据剩余宽度；
   其后依次放扁平“重置”按钮，以及由“开启”文字和 Switch 组成的整体。总开关不得再放
   到 Tab 行，也不得放到滑块左侧。

参考宽度分配：

| 区域 | 宽度 |
| --- | --- |
| 当前值 | `58dp`；只显示两位小数，不重复功能名 |
| 滑块 | `weight = 1`，消化剩余空间 |
| 重置 | `48 × 30dp`，位于滑块右侧，与滑块间隔 `6dp` |
| 开启整体 | `80 × 36dp`，位于重置右侧，与重置间隔 `8dp` |
| 开启文字与 Switch | 间隔 `4dp`；二者是一个整体，不在内部制造大间距 |

### 行为与自动化契约

- “重置”清空本次美颜模块全部 leaf feature 的 desired value，恢复默认活动磨皮/美白类型，并立即刷新当前标签和滑块；不得只重置当前可见项却使用全局“重置”文案。
- 总开关关闭时保留 desired value，只把实际应用值降为零；再次开启时恢复已有值。
- 每个分类记住最后选中的功能项。面板收起、展开不改变分类、选择或强度。
- 封面由资源工作线程解码为 `Bitmap`，以 `<category>:<item-id>` 为 key 传给模板的
  `setCovers(...)`；View 内禁止执行 assets、文件或网络 I/O。封面缺失或解码失败时只对
  该项回退为名称首字占位，不影响其他项、素材安装或 availability。生成
  `NveCompactBeautyPanelView` 后，宿主必须在资源发布完成时实际调用 `setCovers(...)`；
  仅保留模板方法但从不绑定封面数据，视为未完成接入。
- 分类/功能项点击只更新 UI 选择、标签和滑块位置，**不得把该项已有值再次提交给 SDK**，
  也不得为切换项请求一次特殊渲染。效果写入只能由用户实际拖动滑块、显式重置、生命周期
  恢复或总开关状态迁移触发；写入层还必须忽略与 applied state 相同的值。否则美型/微整形
  在 `A → B → A` 快速切换时会重复注册形变参数，产生人脸轻微抖动。
- 使用稳定语义标识：`nve-beauty-entry`、`nve-beauty-master`、`nve-beauty-reset`、`nve-beauty-intensity`、`nve-beauty-tab-<category>`、`nve-beauty-feature-<feature-id>`。
- 自动化必须确认 `nve-beauty-reset`、`nve-beauty-intensity` 和
  `nve-beauty-master` 位于同一调节行，顺序为滑块、重置、开启整体；“开启”文字与 Switch
  属于同一父容器，父容器与重置间隔 `8dp`。同时确认功能项包含 `ImageView` 和正式名称，
  再覆盖展开、分类切换、拖动、重置和收起。
  对选择行为增加调用计数断言：只点击分类/功能项时 SDK setter 计数保持不变；实际拖动后
  只增加一次；`A → B → A` 不产生额外 setter、控制器重绑或画面几何跳变。

## 紧凑美妆面板基线

当客户工程没有可复用设计体系或效果编辑器，且用户没有指定其他布局时，使用
`--ui-profile compact-makeup` 生成 `NveCompactMakeupPanelView.java`。宿主已有 Views、
Compose 或产品设计体系时不生成，只迁移状态语义。

- 复用紧凑美颜面板的深色半透明底板、圆角、描边、强调色、统一入口栏中的
  `64 × 32dp` 入口和 `36dp` chip。入口始终显示“美妆”。
- 面板从上到下固定为：**具体效果项行 → 一级分类行 → 可选状态提示**。效果项和分类均为
  单行横向滚动，不因完整九分类压缩文字。
- 一级分类按“妆容、口红、眉毛、眼影、睫毛、眼线、腮红、修容、高光、美瞳”排序；
  部分接入只生成请求范围内的分类，不创建空页签。
- 每个分类的第一个效果项是“无”。妆容分类显示真实组合妆素材；单妆分类只显示真实单妆
  素材，不得插入虚拟且默认选中的“组合妆”项。
- 单妆和妆容元数据声明封面时，具体效果项必须展示封面并在下方保留正式名称，不能退化为
  纯文字 chip。默认卡片参考宽高为 `60 × 68dp`、相邻项右间距为 `6dp`，与紧凑滤镜列表
  对齐；封面预览为 `44 × 44dp`。选中态使用
  `2dp` 强调色描边，不用强调色实底遮盖封面。封面应在资源工作线程解码后作为数据传入
  面板，分类切换和列表重建不得执行 assets、文件或网络 I/O。封面不可读时单项回退为
  稳定文字占位，不影响素材安装状态和其他条目。
- “无”参考滤镜面板使用同尺寸图文卡片：预览区居中显示统一的圆圈加斜杠图标，下方显示
  “无”。选中时改变预览框描边和图标颜色，不得使用整块粉色实底覆盖卡片。默认模板通过
  `noneIconResource` 接收宿主图标资源，以便和滤镜复用同一视觉资产或语义等价资源。
- 妆容分类支持多个真实组合妆素材，使用稳定 item ID 分别维护选中态；不得把面板构造函数
  或状态对象写死为单个组合妆。UI 状态由 `NveMakeupSelectionState` 统一提供，面板本身
  不再维护第二份 `selectedSingles` 或根据 SDK 对象猜测选中态。
- 组合妆作为基础层，单妆只覆盖对应分类。覆盖后妆容仍保持选中；妆容“无”只清除仍来自
  组合妆的组成项，保留显式单妆。完整状态规则以 [美妆契约](makeup.md) 为准。
- 使用稳定语义标识：`nve-makeup-entry`、`nve-makeup-tab-<category>`、
  `nve-makeup-none-<category>`、`nve-makeup-item-<item-id>`。
- 自动化至少覆盖：展开/收起文字不变、效果项位于分类上方、分类切换不新增虚拟选项、
  已声明封面的真实条目存在 `ImageView` 且非空、妆容叠加单妆后仍选中、单分类“无”
  不清其他分类、妆容“无”保留显式单妆。
  默认 Views 模板可使用 `scripts/verify_makeup_interactions.py`，按真实组合妆和单妆
  item ID 在 adb 设备上执行这条关键路径。

## 紧凑滤镜与道具面板基线

当目标工程没有可复用效果编辑器且需要默认 Views 验证入口时，滤镜使用
`--ui-profile compact-filter`，道具使用 `--ui-profile compact-face-prop`。两者复用美颜/
美妆的深色半透明底板、统一入口栏中的 `64 × 32dp` 稳定入口、粉色强调描边和
贴底面板布局。

- 两个模板的数据项只接收资源线程已准备好的稳定 ID、正式名称、`Bitmap` 封面和
  availability；View 内禁止读取 assets、文件或网络。
- 滤镜固定为“封面项单选行 → value/slider/reset 行 → 可选状态”。条目触摸区为
  `60 × 68dp`，相邻间距 `6dp`；封面框固定为 `48 × 48dp`，内部 Bitmap 区为
  `44 × 44dp`。名称使用 `10sp`、单行省略，位于封面框下方独立的 `16dp` 区域，顶部
  间距 `1dp`；名称不得进入封面框或挤占 Bitmap 空间。元数据提供可读封面时必须显示；
  未提供或解码失败时保留中性预览框和正式名称，不阻塞滤镜安装及其他条目。
- 未选中封面框使用 `1dp` 弱描边，选中时只把**封面框**改为 `2dp` 强调色描边并把名称
  改为白色；条目根容器和名称区不得出现选中边框，也不得用强调色实底覆盖封面。封面图
  使用 `CENTER_CROP` 和圆角裁切，图片自身不承担选中背景。
- 首项“无”与普通滤镜使用相同尺寸和两层结构：预览框内显示圆圈加斜杠图标，框外显示
  “无”。默认模板通过 `noneIconResource` 接收宿主图标资源；选中时仅改变预览框描边、
  图标和标签颜色。
- 强度范围 `[0,1]`，默认 `0.5`。调节行顺序固定为 `value → slider → reset`：数值区
  `58 × 36dp`，重置为 `48 × 30dp`，与滑块间隔 `6dp`。重置使用 `11sp` 次级文字、
  `8dp` 圆角和弱透明表面色，无描边、无阴影、无强调色胶囊实底，并保留轻量按压态；
  未选滤镜或运行时未就绪时，滑块和重置同时禁用。
- 选择相同安装返回 package ID 的展示别名只更新 UI，不触发 coordinator remove/add。
- 道具只有单行紧凑封面卡片和可选状态，不创建强度滑块。道具卡片与滤镜卡片保持相同的
  `60 × 68dp` 触摸区、`48 × 48dp` 预览框和 `44 × 44dp` 图片区；选中描边只画在预览框，
  条目根容器不得再画第二层边框。名称存在时显示正式名称，只有封面时隐藏标签行并使用
  `GONE` 释放高度，使预览框在触摸区内上下居中；名称和封面都缺失时才由数据层提供稳定
  回退名称。当且仅当当前列表至少一个具体道具有可见名称时，“无”才显示下方文字，否则
  同样隐藏标签行并保持居中。默认模板通过 `noneIconResource` 复用滤镜的“无”图标资源。
- 稳定语义标识分别使用 `nve-filter-entry`、`nve-filter-none`、
  `nve-filter-item-<id>`、`nve-filter-intensity`、`nve-filter-reset`，以及
  `nve-face-prop-entry`、`nve-face-prop-none`、`nve-face-prop-item-<id>`。
- 同时接入一个或多个模块时，使用共同生成的 `NveCompactEffectEntryBar` 接管入口布局和
  `ExpansionListener`：构造时传入全部面板，将 `detachEntryButton()` 返回的入口放进等权
  槽位。先按入口顺序用 `createPanelLayoutParams()` 把各面板作为全屏透明覆盖层添加到预览
  根 `FrameLayout`，再把入口栏添加在面板之后；需要保留在最上层的宿主相机控件最后添加。
  非 edge-to-edge 页面用 `createBottomLayoutParams()`；edge-to-edge 页面把宿主已计算的底部
  WindowInset 像素传给 `createBottomLayoutParams(bottomInsetPx)`，模板会在其上追加 `8dp`
  间距。任一模块展开即收起其余模块并隐藏整栏；面板外点击收起后恢复整栏。不得另写平移
  偏移或允许多个面板叠层。
- 自动化至少覆盖滤镜选择/强度/重置/共享包别名/“无”/恢复，以及道具切换/“无”完整关闭/
  恢复；滤镜结构检查必须确认名称位于封面框之外、选中描边只包围封面、重置为扁平按钮。
  视觉检查还必须确认封面未被大面积实底遮挡、道具没有虚构滑块、多个模块不叠层。

## 状态与交互约束

- UI 只更新 desired state；只有 `RUNNING && available` 时调用 SDK。初始化、模型或素材未就绪时禁用相关控件并显示简短原因。
- “选择了哪个调节项”是纯 UI state，不是 effect desired state。选择处理器不得调用
  `onValueChanged(feature, storedValue)`、SDK setter、控制器重绑或渲染请求；只允许滑块的
  用户输入回调更新该 feature 的 desired value。程序化刷新滑块时使用静默更新/回调抑制标志。
- 状态至少覆盖未就绪、加载/安装中、可用、选中、不可用/失败和重置后状态；失败不能留下“已选中但画面无效”的假状态。
- 滑块显示契约范围和当前值，拖动中合并高频更新；不在重组、滚动或滑块回调中创建控制器、安装素材或执行文件 I/O。
- 实时相机预览以新相机帧为唯一渲染时钟。滑块回调只合并最新 desired value，不直接或
  经 helper 调用 `requestRender()`；下一次相机帧到达后再把合并值串行提交给控制器。
- 可滚动父容器不得抢占从滑块轨道或按钮开始的拖动；面板展开、收起和旋转后保留与业务规则一致的效果状态。
- 使用稳定的 resource ID、`testTag` 或 `contentDescription` 支持自动化；图标按钮要有 TalkBack 名称，可点击目标原则上不小于 `48dp`。
- 素材型列表优先使用元数据提供的正式名称和封面。人脸道具有封面时不得只显示编号文字：
  只有封面时仅展示封面，名称和封面都没有时才回退稳定编号。“无”入口居中显示统一的
  “圆圈加斜杠”图标；其下方文字遵循当前列表的统一标签策略，并保持 TalkBack 名称和展示
  项 ID 稳定。封面加载失败不得影响“无”入口或其他可用素材。
- 默认验证面板中的道具卡片固定为 `60 × 68dp`，预览框为 `48 × 48dp`，图片区为
  `44 × 44dp`，相邻间距 `6dp`；选中态只使用预览框强调色描边，不得在根卡片追加边框，
  也不用大面积高饱和实底遮盖封面。“无”与普通道具保持同一尺寸和圆角语言。宿主已有
  设计系统时沿用其 token 和尺寸层级，但仍应保持单层选中反馈和统一标签策略。
- 复用项目的颜色和字体可访问性规则；没有明确规则时检查对比度、系统字体缩放、系统栏安全区和手势导航 inset。

## 视觉与运行时验收

涉及 UI 的交付必须在可运行环境中检查；静态文本扫描不能证明布局合理。至少覆盖：

- 面板收起、展开、内容滚动和再次收起；收起后预览可完整操作，展开入口不遮挡关键画面。
- 竖屏展开态记录面板占可用高度比例，并确认人脸中心区域仍可见；超过 `32%` 必须有产品
  设计依据或改为更紧凑的滚动布局。
- 每个请求模块的独立按钮都能打开正确面板；模块切换不会同时叠加多个面板，按钮选中态与实际展开面板一致。
- 目标最小屏幕宽度的竖屏与横屏；无目标定义时至少检查常见手机窄屏。
- 默认字体和 `1.3x` 字体缩放下无文字意外截断、控件重叠、点击区域错位或面板无法收起。
- 刘海、状态栏、导航栏、手势区域和输入法出现时不覆盖关键操作。
- 加载、不可用、素材安装失败、渲染失败、重置、页面重进和 GLContext 重建后的界面状态。
- 滑块连续拖动、快速切换、展开/收起时预览不中断，无明显掉帧或重复资源安装。

优先使用目标工程已有截图测试、Compose/View UI 测试或真机检查。无法运行界面时，报告“UI 静态适配完成，遮挡、横竖屏、字体缩放和手势仍需运行时确认”，不得声明视觉验收通过。
